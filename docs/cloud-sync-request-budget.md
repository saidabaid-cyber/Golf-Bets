# DEV cloud sync request storm — audit and request budget

Baseline: integration/backyard-current, 071a60fa049cee45822f9c3d894b87d4f7fb2524.
Read-only Vercel preview log aggregation for that deployment, previous hour:
326 /api/cloud/sync and 166 /api/cloud/rounds. These are aggregate counts,
not a per-action measurement. Baseline local sync/concurrency tests: 90/90.

## Causes verified before modification

- app/page.tsx schedules a full cloud cycle every 45 seconds while visible.
  CloudSyncGate forces all non-local triggers, even acknowledged/failed hashes.
  An unchanged idle device therefore downloads its entire account repeatedly.
- Compatible 409 recovery dispatches backyard-sync-retry immediately. The
  listener treats this as manual, bypassing the retry deadline. Auth activation
  and online recovery dispatch the same event, sometimes twice.
- A necessary write runs GET → POST → GET. POST only echoes the submitted
  fingerprint, so the second GET downloads the entire canonical account again.
- The cycle compares the full transport fingerprint for in-flight changes,
  including local navigation and merge metadata, instead of canonical data.
- OwnerRoundSync performs GET → PUT on each debounced snapshot/remount, with
  no acknowledged-material guard and an accumulating promise queue. Nested
  personal sliding adjustment timestamps are generated by currentSnapshot()
  during renders and are not excluded by its top-level timestamp stripping.
- OwnerRoundFinalizeSync depends on the round object's identity; renders and
  revisiting a closed card repeat its canonical check.

Other callers audited: local checkpoint/finalization/cancellation/import;
explicit participant-history refresh; legacy migration; owner cancel/finalize;
account session recovery. There is no separate focus listener for generic sync.
Notification/group/social polling does not call these two cloud endpoints.
applyDraft, applyCloudBundle and provider sync callbacks are stable per account.

## Preservation constraints

Keep authenticated account scoping, private/no-store, local durable outbox,
three-way merges, tombstones, compare-and-swap, remembered owner revisions,
concurrent-edit rebase, shared participants and social publication. An active
draft checkpoint and the owner scorecard are distinct records: neither can
replace the other. Do not remove either persistence path or change scoring.

## Corrected request budget

- No interval and no recurrent cloud requests at rest.
- Mount loads once. Coalesced mount/online/visibility events share one flight.
- Foreground refresh checks a canonical hash; an unchanged account returns a
  small private receipt. No full bundle is transferred. Recent checks coalesce.
- Real local changes debounce; unchanged collection rows are omitted from the
  upload using the existing merge semantics. Canonical POST receipt replaces
  the second GET. Legacy ACK-only responses retain the safe GET fallback.
- Owner writes compare normalized material, debounce and retain only latest
  queued capture. Navigation/remount does not rewrite an acknowledged card.
- Automatic failures use bounded exponential backoff; the same failed hash
  cannot restart through visibility/auth events. Manual retry is explicit.
- DEV-only diagnostics contain method, trigger, hash, byte counts, duration
  and result, never identities, tokens or card contents.

The mega QA remains paused. After local checks and DEV deploy, run one measured
minimal QA, record actual counts/bytes, and stop.
